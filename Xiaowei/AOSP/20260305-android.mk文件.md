# Android.mk文件基本格式

## 常用语法

### LOCAL_PATH:=$(call my-dir)

每个Android.mk文件**必须**以定义`LOCAL_PATH`为开始

------

### include $(CLEAR_VARS)

`CLEAR_VERS`变量由`Build System`提供，并指向一个指定的 **GNU Makefile**，由它负责清理很多 `LOCAL_xxx`

------

### LOCAL_MODULE

定义模块名

```makefile
LOCAL_MODULE:=Demo
```

------

### LOCAL_SRC_FILES

定义apk名，一般引用的是模块名

```makefile
LOCAL_SRC_FILES:=$(LOCAL_MODULE).apk
```

------

### LOCAL_MODULE_TAGS

定义哪个版本会编译。user eng tests optional

```makefile
LOCAL_MODULE_TAGS:=optional
```

> user版本
>
> eng版本 
>
> tests版本 
>
> option所有版本都编译（默认）

------

### LOCAL_MODULE_CLASS

指定模块的类型，可不用定义

```makefile
LOCAL_MODULE_CLASS:=APPS
```

> APPS：apk
>
> JAVA_LIBRAYIES：java libraryies库
>
> SHARED_LIBRAYIES：类似于java的libraryies库
>
> EXECUTABLES：

------

### LOCAL_CERTIFICATE

定义签名

```makefile
LOCAL_CERTIFICATE:=PRESIGNED
```

> 你要编译的apk或者源码生成的apk，要使用什么样的签名
>
> platform：平台签名（安卓系统源码的签名），用该签名，该apk就变成了系统应用
>
> PRESIGNED：代表已经签名过了
>
> shared：数据共享的签名，可以共享联系人、电话之类的

------

### LOCAL_PRIVILEGED_MODULE

定义预置的位置

```makefile
LOCAL_PRIVILEGED_MODULE:=false
```

> true：预置在system/priv-app中
>
> false：预置在system/app中
>
> priv-app的权限比app中的高，比如要使用系统限制的权限（比如：android.permission.WRITE_SECURE_SETTINGS)，我们就需要把程序安装到/system/priv-app中

------

### LOCAL_MODULE_SUFFIX

后缀名（模块输出文件名后缀）

```makefile
LOCAL_MODULE_SUFFIX := $(COMMON_ANDROID_PACAGE_SUFFIX)
```

> 指定指定模块编译后生成的文件的后缀名。
>
> `$(COMMON_ANDROID_PACKAGE_SUFFIX)` 是一个系统预定义变量，它的值是 **`.apk`**。
>
> 所以这行代码实际上等价于：
>
> ```
> LOCAL_MODULE_SUFFIX := .apk
> ```
>
> **注意**：通常对于 `APPS` 类型的模块，这个后缀会自动添加，但如果遇到某些特殊情况（如预置 APK 时使用 `LOCAL_SRC_FILES` 指定文件名），显式声明可以避免意外。

------

### LOCAL_SYSTEM_EXT_MODULE（问题：什么是system_ext分区）

预置到哪个分区中

```makefile
LOCAL_SYSTEM_EXT_MODULE := flase
```

> true：预置在system_ext
>
> false（默认）：预置在system中

## 其他语法

### LOCAL_OVERRIDES_PACKAGES

使其他模块不参与编译

```makefile
LOCAL_OVERRIDES_PACKAGES := messaging Mms Message
```

> 在apk编译时，会使 `messaging`、`Mms`、`Message`都不会编译

------

### LOCAL_OPTIONAL_USES_LIBRARIES

指明所需要的库

```makefile
LOCAL_OPTIONAL_USES_LIBRARIES := org.apache.http.legacy androidx.window.extensions
```

------

### LOCAL_DPI_FILE_STEM

定义资源文件的命名模式，用于支持不同屏幕密度下的资源适配。比如：

```makefile
LOCAL_DPI_FILE_STEM := $(LOCAL_MODULE)_$(my_src_arch)_%.apk
```

> `LOCAL_DPI_FILE_STEM`被定义为`ic_launcher`，而屏幕密度变量`LOCAL_DENSITY`的值为`hdpi`，那么根据这些变量生成的资源文件名将是`ic_launcher_hdpi.pn`

------

### LOCAL_DPI_VARIANTS

为了适应不同屏幕密度的设备，可以通过提供不同密度的资源文件。这些资源文件以不同的命名约定存储在项目中，并通过`LOCAL_DPI_VARIANTS`指定哪些密度变种应该被编译和包含在最终的应用中。

```makefile
LOCAL_DPI_VARIANTS := xxxhdpi xxhdpi xhdpi hdpi mdpi
```

# 问题

## 什么是system_ext？

Android 10 之后引入的分区概念，用于存放与系统紧密集成、但可以独立于 framework 更新的扩展模块。通常用于厂商或 Google 的定制服务（如 Google Play 服务、设备个性化服务等）。

与 `LOCAL_PRIVILEGED_MODULE` 的关系：

- `LOCAL_PRIVILEGED_MODULE` 决定是否放到 `priv-app`（高权限应用）。
- `LOCAL_SYSTEM_EXT_MODULE` 决定放到哪个分区（`/system` 还是 `/system_ext`）。

两者可以组合使用：

```makefile
LOCAL_PRIVILEGED_MODULE := true   # 放在 priv-app 中
LOCAL_SYSTEM_EXT_MODULE := true   # 放在 system_ext 分区
```

最终路径为：`/system_ext/priv-app/MyApp/`
