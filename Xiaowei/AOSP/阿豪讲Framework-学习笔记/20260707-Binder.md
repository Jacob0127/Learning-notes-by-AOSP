# 介绍

Binder是一个RPC（Remote Procedure Call）框架。RPC一般基于IPC（Inter-Process Communication）来实现

# IPC原理

不同进程之间的内核地址空间是映射到相同的物理地址。

# Binder是怎么做到用户数据互相访问的

这个原理有什么作用呢？首先， 两个进程之间，用户数据是没有办法互相访问的。但是Binder是可以做到让用户数据互相访问的，那么这是怎么做到的呢？

![image-20260707203146610](C:\Users\64498\AppData\Roaming\Typora\typora-user-images\image-20260707203146610.png)

如图：很简单，根据上面说的原理，我们可以通过将进程A的用户数据，写入到进程A的内核地址空间中去，然后，由于内核地址空间最后都是映射到相同的物理地址中，那么，我们可以在进程B中，获取相同地址进程A中存储的数据，最后，再从进程B的内核地址空间获取数据即可拿到进程A中的用户数据了。

# Binder中的性能优化

上面说的这个流程是还有优化空间的，Binder是怎么优化的呢？Binder通过内存映射来优化该流程。下面用文字描述一下：

Binder通过mmap将进程A中的用户地址空间和内核地址空间中的一个地址映射到了同一块物理内存中，接着，进程B也有一个内核地址空间对应该物理内存地址，这个时候就可以将进程B中的用户数据拷贝到进程B中的内核地址空间去，这样，进程A就可以在用户地址空间看到该数据了，流程图如下：
