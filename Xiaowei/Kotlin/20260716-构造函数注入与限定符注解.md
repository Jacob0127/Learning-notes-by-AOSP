# 构造函数注入与限定符注解

## 概念说明

**依赖注入（DI）** 是一种设计模式：对象不自己创建依赖，而是由外部（DI 框架）在构造时传入。Dagger/Hilt 是 Android 中最常用的 DI 框架。

**`@Inject`** 标注在构造函数上，告诉 DI 框架："这个类需要用这个构造函数来创建实例，构造函数的参数就是它的依赖。"

**`@Qualifier` 限定符** 用于区分同一类型的多个依赖。比如 `@ShadeDisplayAware` 修饰的 `Resources` 和普通的 `Resources` 类型相同，但语义不同——一个关联 Shade 显示器，一个是普通资源。

## 代码示例

```kotlin
class ModesTileMapper
@Inject                                    // ← Dagger 识别这个构造函数进行注入
constructor(@ShadeDisplayAware private val resources: Resources,  // ← 限定符标注的依赖
            val theme: Resources.Theme)   // ← 普通依赖
    : QSTileDataToStateMapper<ModesTileModel> {
```

### 逐行解析

| 部分 | 含义 |
|------|------|
| `@Inject` | 标记构造函数为注入点，Dagger 自动解析参数并传入实例 |
| `constructor(...)` | Kotlin 中显式写 constructor 关键字，以便在上方放注解 |
| `@ShadeDisplayAware` | 自定义限定符注解，告诉 Dagger "我要的是 Shade 专用的 Resources，不是随便哪个 Resources" |
| `private val resources` | 注入的依赖同时声明为类的私有属性，整个类都能用 |
| `val theme: Resources.Theme` | 另一个依赖，默认 public 可见性 |

## 关键要点

- `@Inject` 放在 `constructor` 关键字前面，是 Dagger 构造函数注入的标准写法
- 当同一类型有多个 Provider 提供时，必须用 `@Qualifier` 注解（如 `@ShadeDisplayAware`）来区分
- Kotlin 中如果构造函数有注解，必须显式写 `constructor` 关键字；没有注解时可以省略
- 构造函数参数加 `val`/`var` 后，参数同时成为类的属性
