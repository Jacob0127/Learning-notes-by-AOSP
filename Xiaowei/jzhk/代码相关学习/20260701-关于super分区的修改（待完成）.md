# Super分区是什么

## Super 分区基础概念

### 1. 它是什么

Super 分区是 Android 10 引入的一个**特殊的物理分区**，它的作用是把多个逻辑分区的镜像打包在一个物理容器里。

---

### 2. 引入 Super 分区之前 (Android 9 及以前)

```
物理存储上的独立分区:
┌──────────┐
│  boot    │  固定大小，比如 64MB
├──────────┤
│  system  │  固定大小，比如 3GB
├──────────┤
│  vendor  │  固定大小，比如 400MB
├──────────┤
│  product │  固定大小，比如 200MB
├──────────┤
│  userdata│  剩下的空间
└──────────┘
```

**问题**: 每个分区大小是写死的。某天 system 需要多 100MB、vendor 刚好空着 100MB —— 但这 100MB 没法挪给 system 用，只能重新分区，**用户数据全部丢失**。

---

### 3. 引入 Super 分区之后 (Android 10+)

```
物理存储上的独立分区:
┌──────────┐
│  boot    │
├──────────┤
│          │  ┌─────────────┐
│  super   │  │  system     │  逻辑分区 (动态分配)
│  (物理)  │  │  vendor     │  都在 super 这个大容器里
│  5120MB  │  │  product    │  不再各自独占物理分区
│          │  │  odm        │
│          │  │  system_ext │
│          │  └─────────────┘
├──────────┤
│  userdata│
└──────────┘
```

---

### 4. 新旧方案对比

|                  | 老方案 (Android 9-)          | 新方案 (Android 10+)                |
| ---------------- | ---------------------------- | ----------------------------------- |
| 物理分区数       | 每个逻辑分区独占一个物理分区 | 多个逻辑分区共享一个 super 物理分区 |
| 空间分配         | 固定，改不了                 | 动态，逻辑分区大小在编译时按需分配  |
| 分区满了怎么办   | 重新分区，清空数据           | 在 super 内部调整各逻辑分区大小即可 |
| OTA 是否能改大小 | 不能                         | 能 (Virtual A/B 机制)               |
| 浪费             | 大 (每个分区都要预留余量)    | 小 (共享一个大的容器)               |

---

### 5. 当前项目的 Super 分区

在分区表 XML 中定义:

```xml
<Partition id="super" size="5120"/>   <!-- 5120 MB = 5GB -->
```

物理上它是一块 5GB 的连续存储区域，里面装的逻辑分区:

```
super (5120MB 物理容器)
  ├── system.img         ~2.x GB
  ├── system_ext.img     ~200 MB
  ├── vendor.img         ~400 MB
  ├── product.img        ~1.x GB
  ├── odm.img            ~几十 MB
  ├── vendor_dlkm.img    ~几十 MB
  └── system_dlkm.img    ~几 MB
         (还有 4MB metadata 记录分区表头)
```

每个逻辑分区的实际大小在编译时由构建系统按需要动态分配，不再是写死的。

---

### 6. 与 OTA 的关系

Super 物理分区大小在出厂后就**定死了** (物理分区边界不能改)。OTA 只能在这块固定大小的容器内部重新分配逻辑分区。

所以 super 物理大小必须从一开始就设对。相关的三个值 (`XML super size` / `BOARD_SUPER_PARTITION_SIZE` / `BOARD_GROUP_UNISOC_SIZE`) 一旦不一致，OTA 就会因空间校验失败而拒绝升级。

# 如何正确的修改super分区

## `jzhk_source_project`

首先需要找到修改super分区的文件，第一步找到`jzhk_source_project`，去对应项目中的mk中找到`jzhk_source_project`

这里拿A16项目中的S213_go来举例，它的`jzhk_source_project`是`ums512_lwfq_1h10_go3g_Natv`

### ums512_lwfq_1h10_go3g_Natv

这个`ums512_lwfq_1h10_go3g_Natv`代表什么呢

| 段     | 值               | 含义                                    |
| ------ | ---------------- | --------------------------------------- |
| ums512 | 芯片型号         | UMS512，也就是T610                      |
| lwfq   | 射频/连接变体    | LTE+WiFi+某频段配置（不同客户可能不同） |
| 1h10   | 硬件核型版本     | 1大核+...的具体硬件配置                 |
| go3g   | Go版本+modem类型 | Android Go+3G modem                     |
| Natv   | 构件类型         | Native构建（相对于_go的精简版）         |

使用find命令查找这个ums512_lwfq_1h10_go3g_Natv，能看到以下这个目录

```bash
# 命令
$ find . -name "ums512_lwfq_1h10_go3g_Natv" -type d
# 结果
./VND/device/sprd/sharkl5Pro/ums512_1h10_go/product/ums512_lwfq_1h10_go3g_Natv
```

## ums512_1h10_go_k515.xml和md.mk

根据这个结果找到两个文件，分别是ums512_1h10_go_k515.xml和md.mk，这两个文件就是要修改的super分区文件，名字可能会不一样，两个文件路径如下：

```bash
# md.mk
./VND/device/sprd/sharkl5Pro/ums512_1h10_go/module/partition/md.mk
# ums512_1h10_go_k515.xml
./VND/device/sprd/sharkl5Pro/ums512_1h10_go/ums512_1h10_go_k515.xml
```

这两个文件分别是做什么用的呢？

### ums512_1h10_go_k515.xml

这个文件是给Android编译系统是用的

### md.mk

这个文件是用来给刷机打包工具用的

## 注意

这两个文件中的super分区大小必须一致，否则会导致刷机失败或者ota升级失败问题
