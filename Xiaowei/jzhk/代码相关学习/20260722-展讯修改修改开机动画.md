# 开机动画定制

## 1. 开机动画资源

首先需要一个 `bootanimation.zip` 的开机动画资源，该动画资源需要跟设备屏幕分辨率一致。

### bootanimation.zip 格式说明

`bootanimation.zip` 是一个标准 Android 开机动画包，内部结构如下：

```
bootanimation.zip
├── desc.txt          # 描述文件，定义分辨率、帧率、播放逻辑
├── part0/            # 第一段动画帧（PNG 序列）
│   ├── 00001.png
│   ├── 00002.png
│   └── ...
└── part1/            # 第二段动画帧（循环播放）
    ├── 00001.png
    ├── 00002.png
    └── ...
```

**desc.txt 格式示例**（800×1280 分辨率）：

```
800 1280 30
c 1 0 part0
c 0 0 part1
```

| 行            | 含义                                                         |
| ------------- | ------------------------------------------------------------ |
| `800 1280 30` | 宽度 高度 帧率(fps)                                          |
| `c 1 0 part0` | `c`=循环播放，`1`=播放1次，`0`=停顿0帧，`part0`=图片所在子目录 |
| `c 0 0 part1` | `0`次=无限循环，直至系统启动完成                             |

> **注意**：zip 包必须使用 **store（不压缩）** 模式打包，否则 Android 无法解析：
>
> ```bash
> zip -r -0 bootanimation.zip desc.txt part0 part1
> ```

### logo 图片格式说明

展讯（UNISOC）平台在 uboot/kernel 启动阶段会显示静态 logo 图片，需要准备 5 张 bmp：

| 文件    | 用途          |
| ------- | ------------- |
| `1.bmp` | 充电状态 logo |
| `2.bmp` | 开机状态 logo |
| `3.bmp` | 低电量 logo   |
| `4.bmp` | 过温充电 logo |
| `5.bmp` | 关机充电 logo |

**要求**：

- 格式：24位 BMP
- 分辨率：与设备屏幕分辨率完全一致（如 800×1280）

## 2. 将资源放置在对应项目目录下

将对应资源（开机动画、开关机 logo）放置到 product 目录下：

```
jzhk/product/<项目名>/boot_animation/
├── bootani/
│   └── bootanimation.zip       # 开机动画
└── logo/
    ├── 1.bmp
    ├── 2.bmp
    ├── 3.bmp
    ├── 4.bmp
    └── 5.bmp
```

**关键**：`<项目名>` 必须与项目 mk 文件中 `jzhk_product_folder` 的值一致。

---

## 3. 放置编译资源到 SYS 目录

除了 product 目录的源文件，还需要将开机动画资源放到编译资源路径：

```
SYS/vendor/sprd/open-source/res/bootani/res/
└── bootanimation.zip        # 开机动画（必需）
    # 以下为可选：
    shutdownanimation.zip    # 关机动画
    bootsound.mp3            # 开机声音
    shutdownsound.mp3        # 关机声音
```

如果需要多套动画（适配不同分辨率/不同客户），可以使用序号命名：

```
bootanimation2.zip, bootanimation3.zip, ... , bootanimation10.zip
```

> **注意**：如果缺少这个路径下的 `bootanimation.zip`，即使用了 `boot_res.mk`，编译也不会有任何文件被拷贝。

## 4. 检查 clone_mmi.sh 脚本

检查 `jzhk/script/clone_mmi.sh`，确认是否有该项目对应的 `jzhk_source_project` 分支，以及是否会拷贝到正确的分辨率目录。

### 如何查找 jzhk_source_project

在项目根目录执行：

```bash
. mk show
```

或直接查看项目 mk 文件：

```
jzhk/mk/<项目>.mk

# 示例内容：
jzhk_source_project = ums9230_full_64only    ← 这个值
jzhk_product_folder = t40_d4xef_t615_hd_800_1280_yunji_P03D_incell_256GB_6GB
```

### clone_mmi.sh 的分支结构

```bash
if [ ${jzhk_source_project} == 'ums9230_6h10_go_Natv' ]; then
    → bmp_file_720P_1080P
elif [ ${jzhk_source_project} == 'ums9621_1h10_native' ]; then
    → bmp_file_1080_1920
elif [ ${jzhk_source_project} == 'ums9230_full_64only' ]; then
    → bmp_file_800_1280
else
    → bmp_file_1080_2400  # 默认
```

**如果项目是新 platform/分辨率**，需要新增一个 `elif` 分支，将 logo 拷贝到正确的分辨率目录：

```bash
elif [ ${jzhk_source_project} == '<你的值>' ]; then
    cp -a -p $jzhk_product_path/$jzhk_product_folder/boot_animation/logo/*.bmp \
        VND/vendor/sprd/release/bmp/unisoc_bmp/boot_logo_resource/bmp_file_<分辨率>
```

目标分辨率目录从以下选择：

- `bmp_file_540_1200`
- `bmp_file_720P_1080P`
- `bmp_file_720_1280`
- `bmp_file_720_1560`
- `bmp_file_800_1280`
- `bmp_file_1080_1920`
- `bmp_file_1080_2400`

## 5. 引入 boot 资源配置

需要确认 `SYS/build/make/target/product/base_system.mk` 是否已引入 `boot_res.mk`：

```makefile
$(call inherit-product, vendor/sprd/open-source/res/bootani/boot_res.mk)
```

如果少了这一行，开机动画资源将不会被打包进系统镜像，**开机动画无法生效**。

### 为什么是 base_system.mk 这个文件？

**原因一：它本身就管理 bootanimation**

`base_system.mk` 第 49 行已经把 `bootanimation` 这个系统程序列入 `PRODUCT_PACKAGES`——也就是说，Android 系统开机动画的播放器二进制就由这个文件负责引入。现在通过 `inherit-product` 把播放器要读取的资源文件（zip/mp3）也挂上来，逻辑上完全内聚。

```makefile
# base_system.mk 第49行：
PRODUCT_PACKAGES += bootanimation \
```

**原因二：继承链的公共基座**

```
base_system.mk    ← 在这里加一行，所有项目自动生效
    ↑ 被继承
base.mk / handheld_system_ext.mk / media_system.mk 等
    ↑ 被继承
各设备 product 定义（如 ums9230_full_64only）
```

`base_system.mk` 是所有 Android 构建的根级基础产品定义文件，所有设备最终都继承它。在这里改一次，所有项目自动生效，不需要在每个项目的 mk 里重复配置。

**原因三：不适合放在其他文件中**

有人可能会想放在 `SYS/device/sprd/sys_mpool/module/product/app/main.mk`，这不可取：

- `main.mk` 是通过 `md-add` 机制按模块引入的，只有使用了 `sys_mpool` 体系的设备才能编译到，覆盖范围不完整
- `main.mk` 的本职是管理 APP 模块（系统应用），而 bootanimation 是系统层媒体资源，职责不匹配
- `main.mk` 在 BSP 模块目录下，多项目多客户都可能修改，冲突概率高

## 6. boot_res.mk 文件内容详解

### 6.1 文件位置

```
SYS/vendor/sprd/open-source/res/bootani/boot_res.mk
```

### 6.2 整体结构

```makefile
# 定义资源源路径
LOCAL_PATH:= vendor/sprd/open-source/res/bootani/res
LOCAL_WALLPAPER_PATH:= vendor/sprd/open-source/res/bootani/wallpapers
```

`LOCAL_PATH` 指向存放开机动画资源的目录。后续所有 `$(LOCAL_PATH)/bootanimation.zip` 都从这个目录读取。

### 6.3 核心机制：条件拷贝

文件用 `$(wildcard ...)` 实现了"存在才拷贝"的机制：

```makefile
ifeq ($(LOCAL_PATH)/bootanimation.zip ,$(wildcard $(LOCAL_PATH)/bootanimation.zip))
PRODUCT_COPY_FILES +=   \
    $(LOCAL_PATH)/bootanimation.zip:$(TARGET_COPY_OUT_SYSTEM)/media/bootanimation.zip
endif
```

**逐行解释**：

| 部分                                          | 含义                                                         |
| --------------------------------------------- | ------------------------------------------------------------ |
| `$(wildcard $(LOCAL_PATH)/bootanimation.zip)` | Make 内置函数，检查文件是否真实存在。存在则返回文件路径，不存在返回空 |
| `ifeq (A ,B)`                                 | 比较 A 和 B 是否相等。如果 `wildcard` 返回了路径（文件存在），则相等，进入 `if` 分支 |
| `PRODUCT_COPY_FILES +=`                       | Android 编译变量，将文件从源路径拷贝到目标路径（system 镜像内） |
| `$(TARGET_COPY_OUT_SYSTEM)`                   | 代表 system 分区的挂载点，最终展开为 `system`                |
| `源:目标`                                     | 冒号左边是编译主机上的文件路径，右边是设备 system 镜像内的目标路径 |

**设计意图**：如果你放了一个 `bootanimation.zip`，它就自动打包进去；如果不放，就什么也不做。不需要额外配置。

### 6.4 支持的四类资源

每套编号（default ~ 10）都支持 4 种资源：

| 资源     | 命名                    | 目标路径                             |
| -------- | ----------------------- | ------------------------------------ |
| 开机动画 | `bootanimation.zip`     | `system/media/bootanimation.zip`     |
| 关机动画 | `shutdownanimation.zip` | `system/media/shutdownanimation.zip` |
| 开机声音 | `bootsound.mp3`         | `system/media/bootsound.mp3`         |
| 关机声音 | `shutdownsound.mp3`     | `system/media/shutdownsound.mp3`     |

### 6.5 多套动画机制（编号 2~10）

文件支持最多 10 套独立的开关机动画资源：

```
default:  bootanimation.zip      → system/media/bootanimation.zip
第2套:    bootanimation2.zip     → system/media/bootanimation2.zip
第3套:    bootanimation3.zip     → system/media/bootanimation3.zip
...
第10套:   bootanimation10.zip    → system/media/bootanimation10.zip
```

这样设计的目的是：同一套固件可以内置多套动画，系统运行时根据 SIM 卡、地区、品牌等条件**动态选择**要播放的动画。

### 6.6 壁纸拷贝

文件末尾还有一段壁纸拷贝逻辑：

```makefile
###copy wallpaper###
ifeq ($(LOCAL_WALLPAPER_PATH),$(wildcard $(LOCAL_WALLPAPER_PATH)))
PRODUCT_COPY_FILES += \
    $(call find-copy-subdir-files,*,$(LOCAL_WALLPAPER_PATH),system/ibingo/wallpapers)
endif
```

将 `vendor/sprd/open-source/res/bootani/wallpapers/` 下的所有文件拷贝到 `system/ibingo/wallpapers/`。属于附加功能，与开机动画无直接关系。

## 附录：完整操作检查清单

为项目添加/修改开机动画时，按以下顺序逐项检查：

- [ ] 1. 制作好 `bootanimation.zip`（分辨率匹配、store 压缩）
- [ ] 2. 制作好 5 张 logo bmp 图片（24位、分辨率匹配）
- [ ] 3. 资源放入 `jzhk/product/<项目名>/boot_animation/bootani/` 和 `logo/`
- [ ] 4. 资源放入 `SYS/vendor/sprd/open-source/res/bootani/res/`
- [ ] 5. 检查 `jzhk/mk/<项目>.mk` 中 `jzhk_product_folder` 指向正确的 product 目录
- [ ] 6. 检查 `jzhk/script/clone_mmi.sh` 有对应 `jzhk_source_project` 的分支，且分辨率目录正确
- [ ] 7. 确认 `SYS/build/make/target/product/base_system.mk` 已引入 `boot_res.mk`
- [ ] 8. 编译验证：`system/media/bootanimation.zip` 是否存在于刷机包中
